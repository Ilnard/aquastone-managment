# Aquastone Management

Локальная разработка сайта управления процессами производства.

## Подключение PostgreSQL

1. Убедитесь, что локальная служба PostgreSQL запущена.
2. Откройте `.env` и укажите пароль роли `postgres` в `PGPASSWORD`. Если база создана под другим именем или пользователем, поменяйте `PGDATABASE` или `PGUSER`.
3. Запустите проект командой `npm run dev`.

При первом запуске API создаёт таблицу `processes`. Номер процесса хранится как уникальный ключ, остальные поля — как JSONB, чтобы добавлять поля процесса без миграции на каждый новый атрибут. Интерфейс показывает статус подключения в верхней панели.

Откройте адрес Vite, который появится в терминале. API работает на `http://127.0.0.1:3001`, а `/api` в dev-среде проксируется к нему.

## API

- `GET /api/health` — статус подключения к базе.
- `GET /api/processes` — список процессов.
- `POST /api/processes` — создать процесс; номер обязателен и должен быть уникальным.
- `PUT /api/processes/:id` — обновить процесс.
- `GET /api/processes/:id/attachments` — список вложений.
- `POST /api/processes/:id/attachments` — загрузить фото, PDF, DWG или DXF до 50 МБ.
- `GET /api/processes/:id/attachments/:attachmentId` — скачать вложение.
- `DELETE /api/processes/:id/attachments/:attachmentId` — удалить вложение.

Файлы сохраняются в локальном каталоге `uploads/`, а их сведения — в таблице `process_attachments`. Каталог исключён из Git; для размещения на хостинге понадобится постоянное файловое хранилище или подключённый диск.

## GitHub Pages

Для публикации используйте `npm run deploy -- "Сообщение коммита"` из ветки `main`. Команда создаёт коммит с этим сообщением в `main`, собирает статическую демо-версию и создаёт коммит с тем же сообщением в `deploy`, затем отправляет обе ветки в GitHub. Если сообщение не указано, команда запросит его в терминале. Для GitHub Pages в настройках репозитория выберите **Settings → Pages → Deploy from a branch → deploy → /(root)**.

GitHub Pages раздаёт только статические файлы: PostgreSQL API и загрузка вложений там не работают. В Pages интерфейс использует браузерное хранилище; общая многопользовательская версия должна размещаться на хостинге, который запускает Express API, и иметь доступ к PostgreSQL и постоянному файловому хранилищу.

API слушает только `127.0.0.1`. Эта локальная заготовка предназначена для разработки и пока не содержит входа сотрудников или серверной проверки прав. Перед публикацией в интернете необходимо добавить авторизацию и разграничение доступа на сервере.
